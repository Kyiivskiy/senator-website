# SENATOR — сайт салону чоловічої класики

Сайт салону чоловічого одягу «СЕНАТОР» (Миколаїв), офіційного представника
бренду HERMOSE в Україні: головна сторінка-візитка плюс каталог-вітрина
без онлайн-продажу.

## Стек

Простий HTML/CSS/JS без збірки та залежностей (обрано свідомо, за запитом,
замість Next.js/React зі супровідного технічного брифа):

- `index.html` — головна: hero, «Образи» (лукбук), HERMOSE, «Про салон»
  разом з «Процесом», «Контакти» з картою, footer.
- `catalog.html` + `product-*.html` — вітрина. Сторінки товарів не пишуться
  руками: їх генерує `scripts/build_catalog.py` з `data/products.json`.
- `css/styles.css` — дизайн-система (CSS custom properties), верстка,
  адаптив, анімації, підтримка `prefers-reduced-motion`.
- `js/main.js` — фіксований хедер, мобільне меню, галерея товару,
  scroll-reveal через `IntersectionObserver`.
- `js/catalog.js` — фільтри, сортування і сітка каталогу.
- `js/leads.js` — форма консультації та відправка заявки на бекенд.

Сайт тільки українською: англійської версії немає, увесь текст лежить прямо
в розмітці.

## Як запустити локально

```bash
python -m http.server 5173
# потім відкрити http://localhost:5173
```

Відкривати `index.html` подвійним кліком теж працює, окрім iframe Google Maps —
йому потрібен http-сервер.

## Як додати або змінити товар

1. Відредагувати `data/products.json` (`id`, `category`, `name`, `price`,
   `sizes`, `images`, за потреби `priceTiers` і `description`).
2. Покласти фото в `images/products/` під іменем з `images`.
3. Запустити генератор:

```bash
python scripts/build_catalog.py
```

Він перезаписує `js/products-data.js` і всі `product-*.html`. **Руками ці
файли правити не можна** — наступний запуск усе затре.

Категорії сайдбара задані окремо, у `CATALOG_STRUCTURE` (`js/catalog.js`), щоб
список не стрибав, коли якась категорія тимчасово порожня. Нова категорія в
`products.json` без запису там не з'явиться у фільтрах.

## Типографіка

`scripts/typography.py` розставляє нерозривні пробіли після коротких
прийменників і сполучників, у цінах і діапазонах — щоб жоден рядок не
закінчувався на «в», «та» чи «і». Генератор викликає його сам; для сторінок,
написаних руками, є окремий запуск:

```bash
python scripts/typography.py
```

## Кеш

Усі локальні `css`/`js` підключені з `?v=N`. Після будь-якої зміни стилів або
скриптів **треба підняти номер в усіх файлах одночасно** (включно з шаблоном
у `scripts/build_catalog.py`), інакше браузери показуватимуть стару версію.

## Що реалізовано

- Адаптив від 320 до 2560 px: мобільне меню, картки лукбуку в один стовпець,
  картки процесу та факти в колонку.
- Хедер `position: fixed`. Саме fixed, а не sticky: iOS Safari перераховує
  sticky-елемент лише після завершення жесту прокрутки, і поки браузер
  ховає свою панель, шапка відставала від верху екрана — над нею було видно
  смужку сторінки.
- Хедер ховається при скролі вниз і зʼявляється при скролі вгору; легкий
  паралакс hero-фото; заголовки секцій зʼявляються по словах; кнопки мають
  «магнітний» ефект на hover. Усе на чистому JS/CSS, без бібліотек, і все
  вимикається при `prefers-reduced-motion: reduce`.
- Доступність: `skip-link`, семантичні `header/nav/main/section/footer`, один
  `<h1>`, видимий `focus-visible`, `aria-label` на декоративних зображеннях,
  безпечні зовнішні посилання (`rel="noopener noreferrer"`).
- Контраст перевірено за WCAG: на світлих секціях акценти й підписи мають
  окремі темні токени, бо яскраве золото на кремовому дає ~1.7:1 замість
  потрібних 4.5:1.
- SEO: `<title>`, meta-опис, Open Graph, локальний SVG-фавікон.

## Заявки

Сайт свідомо **не продає онлайн**: немає кошика й оплати. Єдина дія —
**«Онлайн-консультація»** (`consultation.html`): ім'я, телефон, зручний час
дзвінка. Менеджер передзвонює і розповідає про наявність, розміри й ціни.

Якщо відвідувач натиснув кнопку на сторінці товару, посилання несе
`?product=<id>`: на формі показується назва товару, і вона ж іде менеджеру в
Telegram рядком «Интересует». Кнопка з хедера працює без цього рядка.

Форма чекає на підтвердження бекенда і лише тоді веде на `success.html`.
Якщо відправити не вдалося, вона показує помилку з телефоном салону — краще
так, ніж запевнити клієнта, що заявка пішла, коли вона загубилась. У формі є
приховане поле-пастка (`website`): його заповнюють лише боти, такі заявки
бекенд мовчки відкидає.

### Куди падають заявки

`backend/` — невеликий Flask-бекенд на Render
(`https://senator-backend.onrender.com`). Один ендпоінт `/api/notify-lead`
приймає заявку і надсилає повідомлення в Telegram-бот менеджера. Детальніше —
`backend/README.md`.

Безкоштовний план Render присипляє сервіс після 15 хвилин тиші, а холодний
старт — це 20-50 секунд, які клієнт чекає перед формою. Тому
`.github/workflows/keep-backend-awake.yml` пінгує `/api/health` кожні десять
хвилин. GitHub вимикає заплановані workflow у репозиторії, куди 60 днів нічого
не пушили, — тоді його треба увімкнути назад у вкладці Actions.

`ALLOWED_ORIGIN` приймає кілька адрес через кому — бойовий домен і
`http://localhost:5173`, щоб форму можна було перевіряти локально.

Чому Telegram-бот, а не адмін-панель: власник магазину погано користується
ПК, а сповіщення в Telegram просто приходить як звичайне повідомлення в
телефон, не треба нічого вивчати. Адмін-панель лишається варіантом на
майбутнє, якщо заявок стане багато й знадобиться історія та статистика.

**Продаж сайту.** Проєкт робиться на продаж клієнту, а не для власного
використання — тому бот і всі секрети (`backend/.env`, ключ API) зроблені
так, щоб їх можна було легко передати новому власнику: достатньо створити
новий бот через @BotFather і підставити новий токен у змінні середовища на
Render, без змін коду.

## Перевірка

Збірки й лінтера в проєкті немає, тож `npm run lint`/`build` не застосовні.
Перед релізом варто прогнати в headless-браузері: усі сторінки без помилок у
консолі та без битих посилань, відсутність горизонтального скролу від 320 px,
хедер притиснутий до верху на всіх станах, і жоден рядок тексту не
закінчується на короткий прийменник.
