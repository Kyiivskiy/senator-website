# SENATOR — сайт салону чоловічої класики

Односторінковий іміджевий лендинг салону чоловічого одягу «СЕНАТОР» (Миколаїв),
офіційного представника бренду HERMOSE в Україні.

## Стек

Простий HTML/CSS/JS без збірки та залежностей (обрано свідомо, за запитом,
замість Next.js/React зі супровідного технічного брифа):

- `index.html` — семантична розмітка, обидві мовні версії зберігаються в одному DOM
  і перемикаються через JavaScript.
- `css/styles.css` — дизайн-система (CSS custom properties), верстка, адаптив,
  анімації, підтримка `prefers-reduced-motion`.
- `js/main.js` — перемикач мов EN/UA з `localStorage`, sticky-хедер, мобільне меню,
  scroll-reveal через `IntersectionObserver`.

Іміджева частина сайту (`index.html`) — сайт-візитка, без CMS, бази даних чи
цін. Каталог, кошик і чекаут — окремий розділ, докладніше в розділі
«Магазин» нижче.

## Як запустити локально

Сайт повністю статичний, тож підійде будь-який спосіб віддати файли по HTTP
(відкривати `index.html` напряму подвійним кліком теж працює, окрім Google Maps
iframe, який краще працює через http-сервер):

```bash
# Python
python -m http.server 5173
# потім відкрити http://localhost:5173

# або Node (якщо встановлено)
npx serve .
```

## Що реалізовано

- Розділи: hero, смуга фактів, «Про салон», маніфест «Навіщо чоловікові костюм»,
  HERMOSE, «Образи» (лукбук), «Процес», «Історія СЕНАТОРА», «Візит» з картою,
  footer.
- Перемикач `EN / UA` у хедері: миттєво змінює весь текстовий контент сторінки,
  атрибут `lang` у `<html>`, `<title>`, meta-опис, `aria-label` для декоративних
  зображень; вибір мови зберігається в `localStorage`.
- Анімації появи секцій при скролі (`IntersectionObserver`), кінематографічний
  reveal hero-блоку, плавні hover-стани посилань і кнопок. Усе вимикається при
  `prefers-reduced-motion: reduce`.
- Адаптив під 1440 / 1024 / 768 / 390 px: мобільне меню, вертикальні картки
  лукбуку в один стовпець, картки процесу та факти в колонку.
- Доступність: `skip-link`, семантичні `header/nav/main/section/footer`, один
  `<h1>`, логічна ієрархія заголовків, видимий `focus-visible`, `aria-label` на
  декоративних плейсхолдерах-зображеннях, безпечні зовнішні посилання
  (`rel="noopener noreferrer"`).
- SEO: `<title>` і meta-опис перекладаються разом з мовою інтерфейсу, Open Graph
  теги, локальний SVG-фавікон з літерою «S».

## Магазин (каталог / кошик / оплата) — демо-версія

Окремий розділ поряд з іміджевим сайтом: `catalog.html` → `product-*.html` →
`cart.html` → `checkout.html` → `order-success.html`. Іміджевий `index.html`
не змінився по суті, лише додано пункт «Каталог» і іконку кошика в хедер.

**Це демо на заглушках, не продова версія.** За рішенням користувача зараз
навмисно немає ні реальних товарів, ні підключеної оплати — щоб можна було
побачити весь сценарій (каталог → товар → кошик → чекаут → «оплата» →
підтвердження), перш ніж витрачати час на реальні фото, ціни й підключення
банку.

### Структура

```text
data/products.json        — єдине джерело даних про товари (редагувати тут)
scripts/build_catalog.py  — генерує catalog.html і product-*.html з products.json
js/products-data.js       — згенерований JSON товарів, підключається на кожній сторінці
js/cart.js                — кошик на localStorage, рендер кошика/чекауту, форма
catalog.html               — сітка товарів (згенеровано)
product-<id>.html          — сторінка товару, окрема на кожен товар (згенеровано)
js/catalog.js               — сітка каталогу, сайдбар категорій, сортування (рендериться в браузері)
cart.html                  — кошик (написано вручну)
checkout.html               — форма замовлення + підсумок (написано вручну)
order-success.html          — демо-підтвердження замовлення (написано вручну)
```

**Як додати/змінити товар:** відредагувати `data/products.json`, потім
перегенерувати сторінки товарів:

```bash
python scripts/build_catalog.py
```

Це перезапише `js/products-data.js` і всі `product-*.html` (видалить сторінки
товарів, яких більше немає в `products.json`, і створить нові). `catalog.html`
генератор не чіпає — сітка каталогу рендериться в браузері через
`js/catalog.js` напряму з `products-data.js`, тому нові товари й категорії
з'являються там автоматично без перегенерації сторінки. `cart.html`,
`checkout.html`, `order-success.html` теж написані вручну й однакові для всіх
товарів.

### Категорії

Дворівнева структура (група → категорія), сайдбар зліва на `catalog.html`
будується автоматично з унікальних значень `group`/`category` в
`products.json` — новий товар з новою категорією сам зʼявиться в фільтрі,
нічого вручну оновлювати не треба:

- **Одяг** — Костюми, Піджаки, Брюки, Пальто, Сорочки, Жилети, Поло
- **Аксесуари** — Краватки, Метелики, Запонки
- **Взуття** — Челсі, Лофери

Плюс сортування (за назвою, за ціною зростання/спадання) через `<select>` у
тулбарі каталогу. Фільтр і сортування працюють на клієнті, без перезавантаження
сторінки.

### Товари зараз — заглушки

Усі 14 товарів мають Lorem Ipsum-опис, вигадані назви («Сірий костюм», «Білий
костюм» тощо) і однакову ціну **12 000 грн (≈ $300)**. Фото — CSS-плейсхолдери
(іконка костюма на кольоровому фоні з підписом «ФОТО ТОВАРУ»), а не реальні
знімки. Коли зʼявляться справжні назви, ціни, розміри й фотографії — замінити
відповідні поля в `products.json` (для фото знадобиться доопрацювати шаблон
у `build_catalog.py` та рендер у `catalog.js`, зараз обидва розраховані на
CSS-плейсхолдер, а не на `<img>`).

### Кошик і чекаут

- Кошик зберігається в `localStorage` браузера (нічого не надсилається на
  сервер) — типово для демо без бекенда.
- Форма на `checkout.html`:
  - **Контактні дані** — ім'я, телефон, email того, хто оформлює замовлення.
  - **Доставка Новою Поштою** — місто (з автопідказкою, `js/autosuggest.js` +
    `data/np-cities.json`, 167 реальних українських міст) і номер відділення
    (звичайне текстове поле з підказкою "не знаєте номер — уточнимо
    телефоном").
  - **Одержувач** — чекбокс «Одержувач - я» (за замовчуванням увімкнено); якщо
    зняти галочку, з'являються окремі поля імені й телефону одержувача (на
    випадок замовлення в подарунок).
  - **Примітки до замовлення** — необов'язкове поле-коментар.
- Кнопка «Оплатити карткою» **не підключена до LiqPay**. Зараз вона валідує
  форму, зберігає демо-замовлення в `sessionStorage` (включно з контактами,
  доставкою, одержувачем і примітками — структура вже готова під реальний
  бекенд), очищує кошик і показує `order-success.html`, щоб можна було
  побачити весь сценарій. На сторінці чекауту є жовта техпримітка про це.

**Автопідказка міст — чому не через живе API Нової Пошти.** Публічне API
Нової Пошти вимагає реєстрації бізнесу на devcenter.novaposhta.ua й отримання
ключа (як і LiqPay). Замість цього список міст захардкоджений локально
(`data/np-cities.json`) — це реальні українські міста, не вигадані дані, але
без прив'язки до конкретних відділень (адреси відділень міняються й
відрізняються по місту, видавати їх без живих даних означало б показувати
неправдиву інформацію). Коли зʼявиться ключ Нової Пошти — можна замінити
статичний список на живі запити `getCities`/`getWarehouses`.

**Куди падають замовлення (наступний крок, ще не зроблено).** Обговорили з
користувачем: Telegram-бот замість адмінки. Причина — власник магазину погано
користується ПК, а сповіщення в Telegram просто приходить як звичайне
повідомлення в телефон, не треба нічого вивчати. Технічно знадобиться той
самий невеликий бекенд, що й для LiqPay (не можна безпечно слати повідомлення
з браузера напряму з токеном бота) — тому обидві інтеграції можна зробити
одним заходом. Адмін-панель лишається варіантом на майбутнє, якщо замовлень
стане багато й знадобиться історія/статистика.

### Чек-лист для підключення реального LiqPay (коли магазин погодить акаунт)

LiqPay для змінної суми (кошик з різним підсумком) вимагає підпис запиту
приватним ключем на сервері — це неможливо безпечно зробити тільки в
браузері, JS-файл на клієнті будь-хто побачить. Тому знадобиться:

1. **Публічний і приватний ключ** з кабінету LiqPay/ПриватБанк (бізнес-акаунт
   уже є, за словами користувача — залишилось підключити конкретний магазин).
2. **Невеликий бекенд** (Python/Flask підійде, оскільки на цій машині вже є
   Python, Node не встановлено) з одним ендпоінтом, який приймає кошик,
   формує `data` + `signature` за алгоритмом LiqPay (`base64(sha1(private_key
   + data + private_key))`) і віддає їх фронтенду для редіректу на LiqPay
   Checkout.
3. **Хостинг, що вміє запускати бекенд** — GitHub Pages для цього не підходить
   (тільки статика). Варіанти: Render, Railway, Fly.io, звичайний VPS.
4. **Server-to-server callback** від LiqPay (`server_url`) для підтвердження
   оплати — без цього кроку не можна довіряти статусу «оплачено» лише з
   браузера.
5. ~~**Юридичні сторінки**~~ — чернетки вже готові (`oferta.html`,
   `privacy.html`, `returns.html`), лишилось замінити реквізити на реальні,
   див. розділ нижче.
6. **Фіскалізація** (РРО/ПРРО) — за законом обов'язкова при онлайн-оплаті
   карткою в Україні.
7. Реальні товари, ціни, розміри й фото замість заглушок.

### Юридичні сторінки (`oferta.html`, `privacy.html`, `returns.html`)

Чернетки трьох документів за типовою структурою для українських
інтернет-магазинів: публічна оферта, політика конфіденційності, умови
повернення та обміну (з посиланням на ст. 9 Закону України «Про захист прав
споживачів», 14 днів на повернення товару належної якості).

**Це не юридична консультація.** Перед публікацією:
- Замінити всі плейсхолдери в рамках `[У ДУЖКАХ]` (візуально виділені
  бежевим з коньячною рамкою) на реальні реквізити: назва ФОП/ТОВ, ЄДРПОУ/ІПН,
  адреса, IBAN, телефон, email.
- Показати весь текст, особливо розділ про повернення, бухгалтеру або юристу.

Технічні деталі:
- Мета-тег `robots: noindex` — ці сторінки не мають індексуватися пошуковиками
  окремо від головного сайту.
- Текст документів навмисно **лише українською** (документи регулюються
  законодавством України, перекладати юридичний текст без юриста ризиковано);
  при перемиканні на EN змінюється тільки шапка/футер сайту, а над текстом
  зʼявляється примітка англійською з проханням звертатися за роз'ясненнями.
- На `checkout.html` тепер є обов'язковий чекбокс «Погоджуюсь з умовами
  оферти та політикою конфіденційності» — без нього форма не відправиться.
- Посилання на всі три сторінки додані у футер (`footer-meta`) на всіх без
  винятку сторінках сайту, включно з `index.html`.

## Перевірка

- Розмітка HTML перевірена на збалансованість тегів у всіх 13 сторінках
  (включно з магазином), CSS та JS — на баланс дужок; автоматичний крос-чек
  усіх i18n-ключів в обидва боки по всіх сторінках разом (105 унікальних
  ключів, жодного пропущеного чи «осиротілого»).
- Перемикач EN/UA у кошику й чекауті: динамічно згенеровані рядки (розмір,
  кількість, ціни) раніше «застигали» мовою першого рендеру — виправлено
  через подію `senator:langchange`, яку `main.js` шле при кожній зміні мови,
  а `cart.js` на неї підписаний і перемальовує кошик/чекаут.
- Усі внутрішні якорі (`#salon`, `#hermose`, `#looks`, `#process`, `#story`,
  `#visit`, `#top`) перевірені на відповідність реальним `id` в розмітці.
- Усі зовнішні посилання (`hermoseonline.com`, Instagram, Google Maps) мають
  `target="_blank" rel="noopener noreferrer"`; Instagram і Google Maps
  відповідають `200 OK`. `hermoseonline.com` блокує автоматизовані запити
  (бот-захист) — не вдалося перевірити скриптом, варто відкрити вручну.
- Усі файли в `images/` та `video/` дійсно використовуються в CSS/HTML;
  зайвих файлів немає.
- Приберано мертвий код: невикористаний CSS-клас `.section-dark`, старе
  правило `.media-placeholder--story` (лишилося від фото, яке замінили на
  відео), осиротілий рядок перекладу `hero.sideLabel` (елемент видалили
  раніше, переклад забули).
- Немає збірки/лінтера в проєкті (простий HTML/CSS/JS), тож `npm run
  lint`/`build` не застосовні.
- Рекомендується додатково відкрити сайт у браузері на 1440, 1024 та 390 px і
  перевірити перемикач мови та мобільне меню вручну.
