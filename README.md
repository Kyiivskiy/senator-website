# SENATOR — сайт салону чоловічої класики

Односторінковий іміджевий лендинг салону чоловічого одягу «СЕНАТОР» (Миколаїв),
офіційного представника бренду HERMOSE в Україні.

## Стек

Простий HTML/CSS/JS без збірки та залежностей (обрано свідомо, за запитом,
замість Next.js/React зі супровідного технічного брифа):

- `index.html` — семантична розмітка, обидві мовні версії зберігаються в одному DOM
  і перемикаються через JavaScript.
- `css/styles.css` — дизайн-система (CSS custom properties), верстка, адаптив,
  анімації, підтримка `prefers-reduced-motion`.
- `js/main.js` — перемикач мов EN/UA з `localStorage`, sticky-хедер, мобільне меню,
  scroll-reveal через `IntersectionObserver`.

Сайт (`index.html`) — сайт-візитка, без CMS чи бази даних. Каталог — вітрина
без онлайн-продажу; сайт веде відвідувача до заявки на онлайн-консультацію,
докладніше в розділі «Заявки» нижче.

## Як запустити локально

Сайт повністю статичний, тож підійде будь-який спосіб віддати файли по HTTP
(відкривати `index.html` напряму подвійним кліком теж працює, окрім Google Maps
iframe, який краще працює через http-сервер):

```bash
# Python
python -m http.server 5173
# потім відкрити http://localhost:5173

# або Node (якщо встановлено)
npx serve .
```

## Що реалізовано

- Розділи головної: hero, «Образи» (лукбук), HERMOSE (об'єднаний з фактами
  «17 років» і «46-70»), «Про салон» разом з «Процесом», «Контакти» з картою,
  footer.
- Перемикач `EN / UA` у хедері: миттєво змінює весь текстовий контент сторінки,
  атрибут `lang` у `<html>`, `<title>`, meta-опис, `aria-label` для декоративних
  зображень; вибір мови зберігається в `localStorage`.
- Анімації появи секцій при скролі (`IntersectionObserver`), кінематографічний
  reveal hero-блоку, плавні hover-стани посилань і кнопок. Усе вимикається при
  `prefers-reduced-motion: reduce`.
- Додатково: шапка ховається при скролі вниз і зʼявляється при скролі вгору;
  легкий паралакс hero-фото під час скролу; заголовки секцій (`<h2>`)
  зʼявляються по словах (split-text reveal) замість блоку цілком; кнопки
  `.btn-solid`/`.btn-outline` мають "магнітний" ефект - тягнуться за курсором
  на hover. Усе на чистому JS/CSS, без бібліотек (`js/main.js`).
- Адаптив під 1440 / 1024 / 768 / 390 px: мобільне меню, вертикальні картки
  лукбуку в один стовпець, картки процесу та факти в колонку.
- Доступність: `skip-link`, семантичні `header/nav/main/section/footer`, один
  `<h1>`, логічна ієрархія заголовків, видимий `focus-visible`, `aria-label` на
  декоративних плейсхолдерах-зображеннях, безпечні зовнішні посилання
  (`rel="noopener noreferrer"`).
- SEO: `<title>` і meta-опис перекладаються разом з мовою інтерфейсу, Open Graph
  теги, локальний SVG-фавікон з літерою «S».

## Заявки

Сайт свідомо **не продає онлайн**: немає кошика й оплати. Єдина дія —
**«Замовити онлайн-консультацію»** (`consultation.html`): ім'я, телефон,
зручний час дзвінка. Менеджер передзвонює і розповідає про наявність, розміри
й ціни. Це головний CTA сайту — у хедері, в hero, у секції «Контакти» і на
кожній картці товару.

Якщо відвідувач натиснув кнопку на сторінці товару, посилання несе
`?product=<id>`: на формі показується назва товару, і вона ж іде менеджеру
в Telegram рядком «Інтересует». Кнопка з хедера працює без цього рядка.

Заявка йде на Telegram-бекенд (`backend/`, задеплоєний на Render) — менеджер
отримує повідомлення одразу після відправки. Далі користувач потрапляє на
`success.html`. У формі є приховане поле-пастка (`website`): його заповнюють
лише боти, такі заявки бекенд мовчки відкидає.

### Структура

```text
js/leads.js        — форма консультації, відправка заявки на бекенд
consultation.html   — форма запиту консультації
success.html        — підтвердження після відправки заявки
```

### Куди падають заявки

`backend/` — невеликий Flask-бекенд, задеплоєний на Render
(`https://senator-backend.onrender.com`). Один ендпоінт `/api/notify-lead`
приймає заявку з форми консультації і надсилає повідомлення в Telegram-бот
менеджера. Детальніше — `backend/README.md`.

`ALLOWED_ORIGIN` приймає кілька адрес через кому — наприклад, бойовий домен і
`http://localhost:5173`, щоб форму можна було перевіряти локально.

Чому Telegram-бот, а не адмін-панель: власник магазину погано користується
ПК, а сповіщення в Telegram просто приходить як звичайне повідомлення в
телефон, не треба нічого вивчати. Адмін-панель лишається варіантом на
майбутнє, якщо заявок стане багато й знадобиться історія/статистика.

**Продаж сайту.** Проєкт робиться на продаж клієнту, а не для власного
використання — тому бот і всі секрети (`backend/.env`, ключ API) зроблені так,
щоб їх можна було легко передати новому власнику: перед продажем достатньо
створити новий бот через @BotFather і підставити новий токен у змінні
середовища на Render, без змін коду.

## Перевірка

- Крос-чек i18n в обидва боки: 85 ключів у словнику, усі використані в
  розмітці, жодного пропущеного; структура `uk` і `en` збігається.
- Усі 23 сторінки відкриваються без помилок у консолі, без биті посилань і
  порожніх картинок (перевірено скриптом у headless-браузері).
- Контраст тексту перевірено за WCAG: на світлих секціях акценти й підписи
  використовують окремі темні токени, бо яскраве золото на кремовому дає
  ~1.7:1 замість потрібних 4.5:1.
- Відступи зведені на шкалу 8px (4px — половинний крок для іконок і
  підкреслень); поля сітки однакові на всіх сторінках і ширинах.
- Усі внутрішні посилання й ресурси (`.html`, `css/`, `js/`, `data/`)
  перевірені скриптом на існування цільового файлу.
- Усі файли в `images/` та `video/` дійсно використовуються в CSS/HTML;
  зайвих файлів немає.
- Після переходу з магазину (кошик/оплата) на форми заявок прибрано весь
  мертвий CSS: класи кошика, чекаут-сітки з підсумком, вибору розміру/
  кількості, автопідказки міст — усе, що більше ніде не рендериться.
- Немає збірки/лінтера в проєкті (простий HTML/CSS/JS), тож `npm run
  lint`/`build` не застосовні.
- Рекомендується додатково відкрити сайт у браузері на 1440, 1024 та 390 px і
  перевірити перемикач мови, мобільне меню та обидві форми заявок вручну.
